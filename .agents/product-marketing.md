# Product Marketing Context

**Document version:** v1
**Last updated:** 2026-09-09

## Product overview

摸鱼棋局 / Idle Arena 是可在终端试玩的自走棋实验。玩家招募、合成、布阵，对局中的另外七个座位默认由本机 Codex CLI 决策。它是 Python 项目，没有收费服务；Codex 模式使用玩家自己的账户额度。

## Audience and use case

面向喜欢自走棋、终端小玩具和 AI 对手实验的开发者。目标动作是克隆仓库并开始第一回合。用户可以先离线试操作，再使用 Codex 对手。受众与需求是根据实现推导的假设，没有用户规模或市场验证数据。B2B 采购角色不适用。

## Problems and positioning

尝试将自走棋的招募、经济、羁绊和自动战斗放进一个终端窗口。准备阶段没有倒计时，操作自动存档，便于分段试玩。终端的可读性与操作舒适度仍需评估，因此定位为实验版，不宣传成熟游戏体验。

## Alternatives and differences

替代选择包括图形界面的自走棋和其他终端游戏。未做竞品实测，不声称性能、策略强度或体验领先。当前组合特点是七个 Codex 对手、18 个像素角色、中文方向键菜单、无准备倒计时和本地存档。

## Objections

| 顾虑 | 依据与回答 |
| --- | --- |
| 是否必须先配置模型 | 可以显式用 local 模式离线试玩；默认模式仍为 Codex |
| 对手是否真由模型决策 | Codex CLI 输出行动，规则引擎校验后应用；请求失败会显示错误 |
| 会不会消耗很多额度或等待很久 | 每位存活对手每回合 1–2 次请求，最多 3 个并发；耗时取决于模型与网络 |
| 能否替代完整自走棋游戏 | 当前只有核心玩法，没有装备、选秀、强化符文或真人联机 |

不适合期待完整图形体验、无需模型等待或竞技平衡保证的玩家。

## Switching dynamics

吸引点是终端内试玩和观察模型运营。试用阻力是 Python、终端尺寸以及 Codex 配置；通过完整克隆命令、离线入口和明确的首回合操作降低阻力。没有证据表明用户会从其他游戏长期迁移。

## Language and voice

用词：终端自走棋、招募、升星、布阵、自动战斗、试玩、实验版。语气轻松、直接，允许一点游戏感。避免“零成本 AI”“瞬间响应”“最强策略”“金铲铲复刻”“成熟替代品”。没有客户评价或可公开的访谈摘录，不编造证言。

## Proof points

- 18 个独立角色、6 类羁绊、1 名玩家和 7 个对手，可由代码与资源核验。
- 64 项自动测试；40 局离线模拟全部结束，记录在 `validation/`。
- 2026-09-09 七个 Codex 对手完成一轮准备及结算，用时 49.08 秒；该验证中玩家由离线策略代打。只验证一轮，不扩写成真实模型全局稳定性或长期平衡性结论。
- README 预览由游戏实际渲染函数生成，标注离线样例，不冒充实时 Codex 对局截图。

## Goals and publication

本次目标是在作者的私有 GitHub 仓库保存一个清楚、可运行、便于之后继续的快照，预备好将来分享时的项目介绍。是否公开由作者另行决定。主要入口为“开始试玩”；不承诺下一版本或开发时间表。不添加遥测、订阅、营销外发或定时监控。尚无转化率、访客或用户数据。

## Copy decisions

采用标题：“在终端里，和 7 位 Codex 对手下一局自走棋。”它同时交代载体、玩法与区别。

备选：“让 Codex 坐到棋盘对面。”较有记忆点，但需要副标题解释玩法；“招募像素怪兽，看 AI 怎么运营。”更突出角色，但淡化了终端这一使用门槛。没有开展 A/B 测试，不声称转化提升。

首页顺序：一句话说明 → 预览 → 试玩命令 → 三步操作 → 模型成本和范围 → 深入文档。详细规则移入指南，首屏使用完整克隆命令。
