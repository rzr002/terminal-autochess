# 玩法、规则与开发说明

[返回项目首页](../README.md)

以下命令均在项目根目录运行。初次下载与安装见项目首页。

## 操作

只需记住三个操作：

| 按键 | 动作 |
| --- | --- |
| 方向键 | 选择棋子、按钮或菜单项 |
| `Enter` | 确认当前选项 |
| `Esc` | 返回 / 取消移动；主界面打开「更多」 |

**上下切换区域，左右选择内容。** 从商店向上是备战席，再向上是棋盘；从商店向下是操作栏。方向键可以到达每个区域，不需要输入棋子编号或命令。

底部操作栏：

```text
 开始战斗   自动上阵   刷新 2金   升级 4金   锁定商店   更多
```

- 在商店选择棋子，Enter 直接招募。选中时会显示技能与费用。
- 在备战席选棋并确认，选择「上阵」即可自动找一个合适的空位；也可选择「选择上阵位置」，用方向键指定格子。
- 在棋盘选棋并确认，选择「移动位置」后用方向键选落点，再 Enter 放下。落到已有棋子的格子会交换；Esc 取消。
- 选择「更多」可以查看对手、查看玩法说明、隐藏棋局或保存退出。
- 战斗期间，底部按钮变成跳过动画、暂停播放、隐藏棋局和保存退出。结算后默认选中「下一回合」。

隐藏后按 Enter 恢复。隐藏、暂停或查看菜单时，已经发出的请求可能完成；恢复前不会应用结果或推进战斗。隐藏页只更换终端内容，不影响系统进程列表或外部终端录制。退出会恢复原命令行。

旧的数字买棋和字母快捷键仍兼容，但不是必须操作，也不会占用主界面的提示区域。

## 存档与新局

每次操作和回合结算都会自动保存到项目的 `.saves/autosave.json`。再次运行默认继续，包括已经准备完成的 AI，避免重试时重复扣金币。

```bash
python3 play.py --new                         # 新局，旧存档自动备份
python3 play.py --save .saves/lunch.json       # 独立存档
python3 play.py --model 你的模型ID              # 续玩时更换模型
```

存档会记录对手来源。继续 Codex 存档时不会把对手换成本地策略；需要另一种模式时用不同存档或加 `--new`。损坏的存档会报错并保留原文件。

## 规则

- 你 + 7 位对手，初始 **60 血、10 金、2 级**。等级等于上阵人口，最高 8 级；棋盘是己方 3×7 格、敌方 3×7 格；备战席 8 格。
- **三枚同名同星自动合成**，最高三星。二星基础生命 / 攻击是单星的 1.8 倍，三星为 3.24 倍。合成优先保留棋盘上的位置。
- 商店每次提供 5 枚棋子，共 1–4 费，等级越高出现高费棋子的概率越大。每人的商店独立抽样，**这一版不含共享卡池**。
- 新回合收入：基础 5 金 + 每持有 10 金获得 1 金利息（最多 5）+ 每 2 连胜或连败获得 1 金（最多 3）。战斗胜利立即 +1 金。出售返还该星级包含的所有棋子的原价。
- 每个新回合自动 +2 经验。升级消耗：2→3 为 4，随后分别为 8、12、20、28、36。
- 战斗按距离移动和选取目标，包含射程、护甲、法力、治疗、范围伤害与技能；进攻和受击都积攒法力，满 100 时在下一次攻击时施放技能。
- 战斗每步代表半秒。60 秒后进入持续扣血的加时，最多 90 秒。模拟时间与动画播放速度独立。
- 失败扣血 = `2 + floor(回合/3) + 敌方存活棋子数`。平局双方只扣前两项。奇数玩家时一人对战镜像阵容，镜像原主不会重复结算。
- 只剩一位存活玩家，或完成第 30 回合时结束。存活者按血量、金币排序；淘汰者按淘汰回合、金币排序，同条件用固定座位顺序。你被淘汰后可继续观战。

羁绊只统计**上阵的不同名字**，同名重复上阵不增加计数：

| 羁绊 | 2 / 4 单位效果 |
| --- | --- |
| 霓虹 | 霓虹单位攻击 +15% / +30% |
| 荒野 | 荒野单位每秒回复 2% / 4% 最大生命 |
| 星界 | 星界单位初始法力 +30 / +60 |
| 守卫 | 守卫生命 +20% / +40%，护甲 +15 / +30 |
| 游侠 | 游侠攻击间隔 -20% / -35% |
| 术士 | 术士技能效果 +30% / +60% |

这是可玩的首版，暂未实现装备合成、选秀、野怪、强化符文、六边形棋盘与联网真人匹配。

## Codex 对手怎样玩

7 个对手分别偏向星界法术、荒野续航、霓虹快攻、游侠后排、守卫前排、追星和经济速升。每个座位独立调用 Codex；只给模型它自己的棋子 / 商店、公开对手棋盘和游戏规则。不给其他商店、备战席或随机数状态。

模型一轮输出一批出售、买经验、买棋、完整布阵和锁店操作；可以额外请求一次刷新，再对新商店独立决策。因此每位存活 AI 每轮需要 **1–2 次模型请求**，最多 3 个请求并发。战斗本身在本地演算。

程序使用官方 [Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode) 的 `codex exec` 和 JSON Schema 接收行动。临时目录运行、只读沙箱、临时会话，关闭 shell、apps、plugins、hooks、memories 和 multi_agent；忽略用户工具配置，沿用本机认证并单独读取模型 ID。macOS 系统代理会传递给 CLI 子进程。

所有操作先在副本上校验，再整体应用。网络、超时或非法行动会停留在当前准备回合，选择「重试连接」，或从「更多」保存退出。已成功完成的对手无需重新行动。失败不会悄悄改用本地策略。

模型请求会使用你的 Codex 账户额度。实际延迟取决于网络、模型及输出；本项目仅验证了可运行性，没有声称模型经过自走棋强化学习训练或具有竞技强度。

```bash
python3 play.py --check-codex                  # 一次真实请求和规则校验
python3 play.py --check-codex --model 模型ID
```

## 逐行模式与测试

```bash
python3 play.py --plain
```

使用 `buy 1`、`auto`、`move 棋子编号 0..20`、`move 棋子编号 bench`、`sell 棋子编号`、`refresh`、`xp`、`fight`、`next`、`quit`。棋盘格从 0 起始，0–6 是前排、14–20 是后排。逐行模式不播放动画，模型等待期间不能即时使用隐藏键；建议使用全屏模式。

```bash
python3 -m unittest discover -s tests -v
python3 play.py --headless --agent local --seed 42 --rounds 30
```

自动测试不会调用真实模型。无界面模式不读写正常存档，玩家座位由本地策略代打，其余 7 位遵循 `--agent`；省略 `--agent` 仍会调用真实 Codex。输出 JSON 包含阵容、对战、名次和模型决策次数。

代码：`autochess/engine.py` 负责规则，`agents.py` 负责对手，`ui.py` 负责终端显示与操作，`__main__.py` 负责启动与模拟。联调结果和终端布局样本保存在 `validation/`。

2026-09-09 本机联调：`gpt-6-astra` 完成一次独立决策校验（18.68 秒），并完成一轮 7 位 Codex 对手的比赛（7 次模型决策，49.08 秒）。全部对手成功买棋、布阵，4 场战斗完成结算，见 [七对手联调记录](../validation/codex-seven-opponents.json)。玩家位由离线策略代打，仅用于此次无界面验证；正常游戏中由你操作。

64 项自动测试通过；另用种子 0–39 完成 40 局离线比赛，均在 16–22 轮内结束，8 个席位均有获胜记录。上述数据验证规则与运行稳定性，不代表长期平衡性或真实模型的整局成功率。

本次菜单交互更新已验证：仅使用方向键与 Enter 完成招募、棋子菜单、上阵、自动开战、下一回合和保存退出；主界面不再要求记忆数字 / 字母快捷键。布局样例见 `validation/menu-80x24.txt` 和 `validation/champion-menu-80x24.txt`。
